## 3. UI 浏览器验证（Playwright）

- 应用启动、四区渲染、WebSocket 连接成功（「已连接」）。
- 文件模式端到端：选源→填路径→开始→轨迹出现 4 个确认音符，历史不被覆盖。
- 切换调性后唱名随调性变化、音名不变（由 solfege 单测 + 数据流保证）。
- 点击节点显示详情、修正后相邻音程重算（trackStore 单测覆盖）。
- 控制台 **0 错误**（favicon 404 已用 `data:,` 修复）。

## 4. 性能观察

- 文件离线处理（1.9s 音频）瞬时完成，无事件积压。
- 实时 loopback 处理 48kHz 立体声，YIN（FFT 加速）+ 切分远快于实时，未观测到队列积压。
- UI 用 rAF 节流快照更新，避免每帧全量重渲染；长期内存增长未做压力测试（列入后续）。

## 5. 已知问题 / 未覆盖

- 完整歌曲多声源主旋律分离：**未实现**（明确不做，非调参问题）。
- 八度误判风险（YIN「首个低于阈值」）：对泛音强音色可能选错八度，未加校正。
- 文件输入仅 WAV；24-bit WAV、MP3/FLAC 不支持。
- 系统音频实时模式不保存原始音频，故「局部回放」未实现。
- 长期运行内存压力测试未做。
- 未引入 ESLint（规格书列为「或等价工具」，类型检查已用 `tsc --noEmit` 覆盖）。

## 6. 结论

核心数据流（音高 → 音符 → 轨迹 → 音程 → 唱名 → UI）已端到端打通并经真实浏览器验证；系统音频捕获经实测可用。首版交付目标达成，未实现的均为规格书允许的「后续独立能力」，已如实列出。
